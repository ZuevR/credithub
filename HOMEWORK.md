# HOMEWORK — домашний стенд: настройка инфраструктуры своими руками

Учебный прогон: повторяем стенд, который уже развёрнут в офисе, но на домашней машине и
**руками пользователя**. Цель — не результат, а понимание: что за чем идёт и почему.

Офисный стенд (для сравнения) описан в [PROGRESS.md](PROGRESS.md) — там же разбор граблей,
на которые мы наступали. Этот файл — про новый прогон.

---

## Правила прогона

1. **Команды выполняет пользователь.** Ассистент не выполняет изменяющих команд вообще.
2. **Ассистент подключается к машине только для чтения** — статусы, логи, проверки. Это
   единственное, для чего нужен SSH-доступ.
3. **Один шаг за раз.** Перед каждым шагом ассистент объясняет: зачем он нужен, что именно
   произойдёт, как поймём, что получилось. Ждём подтверждения.
4. **Проверка после каждого шага** — до перехода к следующему.
5. **Если что-то пошло не так** — не «лечим» наугад: сначала разбираемся, что произошло.
6. Прогресс и выводы фиксируются **в этом файле**, а не только в переписке.

Формат шага:

```
Шаг N: <что делаем>
Зачем:  <какую задачу решает>
Команда: <одна команда или короткий блок>
Ожидаем: <что должно появиться>
Проверка: <как убедимся, что получилось>
```

## Маршрут

Отмечаем по мере прохождения. Порядок неслучаен: каждый этап опирается на предыдущий.

### Этап 0. Разведка (только чтение)

- [ ] Узнать ОС, ядра, ресурсы, что уже установлено
- [ ] Проверить, нет ли занятых портов, которые нам нужны (80, 443, 6443)
- [ ] Проверить выход в интернет (apt, GitHub, реестр образов)

### Этап 1. Подготовка системы

- [ ] `git`, `curl`, `ca-certificates`
- [ ] Решить вопрос с `sudo` (пароль или passwordless — и чем это удобно/опасно)

### Этап 2. Кластер

- [ ] Установить k3s **с `--disable traefik`**
- [ ] Убедиться, что нода `Ready`, системные поды `Running`

### Этап 3. Инструменты управления

- [ ] `kubectl` — **настоящий клиент**, а не симлинк k3s
- [ ] `~/.kube/config` с адресом API по IP, а не `127.0.0.1`
- [ ] Helm **той же мажорной версии, что в кластере**

### Этап 4. Ingress

- [ ] Traefik чартом в свой namespace
- [ ] Проверка: `curl http://<host>/` отдаёт 404 от Traefik (значит слушает, маршрутов нет)
- [ ] Проверка маршрутизации на временном nginx + Ingress (потом удалить)

### Этап 5. Данные

- [ ] Чарт `namespace` (отдельно: это ресурс кластерного уровня)
- [ ] Чарт `postgres`: StatefulSet + headless Service + PVC
- [ ] Проверка, что **данные живут на диске**: записать → удалить под → проверить

### Этап 6. Образы и реестр

- [ ] Решить, куда публикуем образы (GHCR) и как кластер получает к ним доступ
- [ ] Собрать образ первого сервиса
- [ ] `imagePullSecret`, проверить, что под стартует из реестра

### Этап 7. Сервисы

- [ ] core-api (нужна база)
- [ ] BFF (ходит в core-api по DNS-имени сервиса)
- [ ] shell + ConfigMap с адресами remote'ов
- [ ] mfe-credits (статический remote)
- [ ] mfe-calculator (Angular, ES-модуль)
- [ ] mfe-programs (SSR)

### Этап 8. Проверка целиком

- [ ] Снаружи открываются `/`, `/credits`, `/calculator`, `/programs`, `/api/*`
- [ ] В браузере: данные из базы, оба remote'а монтируются, SSR-раздел гидрируется

## Почему именно так: решения и их причины

Короткие ответы на «а почему не иначе» — чтобы это был не набор заклинаний.

**Почему k3s, а не kubeadm или microk8s.** k3s — один бинарник, ставится скриптом, тянет
containerd, ServiceLB и local-path «из коробки». Для одной машины это минимум движущихся
частей; kubeadm требует отдельной настройки CNI, CSI и балансировщика.

**Почему `--disable traefik`.** k3s ставит свой Traefik, но его версией и настройками мы не
управляем. Ставим Traefik сами чартом — тогда обновление и конфигурация под нашим контролем.

**Почему Helm 3, а не 4.** В кластере Helm 3; разные мажоры управляют одними релизами
по-разному, и проверять совместимость на живом кластере не хочется. Обновление до 4 —
осознанный отдельный шаг.

**Почему `local-path`.** Это StorageClass k3s по умолчанию, он создаёт каталог на ноде и
отдаёт его как PersistentVolume. Том привязан к ноде — для однонодового кластера нормально,
для нескольких уже нет (там нужен сетевой CSI).

**Почему чарт `namespace` отдельно.** Namespace — ресурс кластерного уровня. Если бы им
владел чарт сервиса, то `helm uninstall` этого сервиса снёс бы namespace вместе с остальными.

**Почему образы публикуются в реестр.** k3s работает на containerd, а не Docker, поэтому
образ, собранный локально в Docker, кластеру не виден. Варианты: публиковать в реестр
(ближе к проду) или импортировать в containerd вручную (годится для однонодового стенда).

**Почему секреты создаются заранее `kubectl`, а не через `helm --set`.** Значение из
`--set` оседает в истории команд. Пароль создаём отдельным Secret, чарт его только читает.

## Грабли, которые уже известны

Список того, на что мы наступали в офисе. Полезно знать заранее — но лучше понимать, почему
каждая возникает.

| Грабли | В чём суть |
|---|---|
| `kubectl` в k3s — симлинк на `k3s` | Читает `/etc/rancher/k3s/k3s.yaml` мимо `~/.kube/config`, поэтому каждая команда требует `sudo`. Нужен настоящий клиент |
| Имя переменной `<СЕРВИС>_PORT` | Kubernetes сам создаёт такие переменные для сервисов namespace (docker-links). `Number("tcp://…")` даёт `NaN`, приложение падает в `listen` с невнятной ошибкой |
| `mjs` нет в `mime.types` nginx | Angular отдаёт ES-модуль, браузер строго проверяет MIME и откажется его исполнять. Ошибка выглядит как «модуль не загрузился» |
| Права файлов из контекста сборки | Если файл попал в образ с режимом `0600`, контейнер под non-root падает с `EACCES` на собственном файле |
| `subPath`-монтирование ConfigMap | Не обновляется при изменении ConfigMap — нужна перекатка пода (аннотация с хешем) |
| Изменяемый тег образа | При `pullPolicy: IfNotPresent` нода берёт прежний образ из кэша, и обновление ничего не меняет |
| Traefik не срезает префикс пути | Запрос приходит в контейнер целиком: приложение должно отвечать по этому префиксу либо нужен `StripPrefix` |
| Кросс-сборка образов | Сборка под чужую архитектуру через QEMU падает с `Segmentation fault` — собирать надо нативно |
| `get.helm.sh` отвечает 404 на корень | Это нормально, но сеть может флапать: большие загрузки стоит повторять |
